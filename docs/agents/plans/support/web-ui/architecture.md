# Architecture and security specification

This is proposed behavior for implementation. Amend the living contracts and allocate new ADR numbers at execution; do not treat this document as an already accepted invariant. Baseline findings and primary references are in [source review](source-review.md).

## 1. Scope and interface

Implement a React SPA in `web/` with strict TypeScript. The main navigation is Library, Operations, Maintenance, and Administration. Library unifies models and datasets. Every repository has a publication-aware detail route; the model page includes variants and the dataset page includes static declarations. Tags are configuration-backed operator labels, not categories, permissions, upstream tags, or a new annotation database. Follow the [prototype](reference/hfcache-web-ui-mockup.html) as an interaction/design reference, not executable production code or a source of actual archive facts.

Do not introduce inference, model loading, GPU/VRAM suitability, quantization conversion, partial-repository downloads, upload, mirror/export, arbitrary remote discovery, README full-text search, new scheduling engines, multi-user management, or repository-level ACLs. Do not add task/language/license filters merely because those declarations appear on a detail page; existing catalog filters determine the first release's search controls.

## 2. One Caddy instance, one API application

The production topology remains:

```text
Browser ------------------ HTTPS -------------------+
CLI / REST bearer clients --------------------------+--> existing Caddy :8443
Read-only MCP clients ------------------------------+          |
                                                        existing API Unix socket
                                                               |
                                                   one hfcache ASGI application
                                                   /ui/*  /api/v1/*  /mcp/*
                                                               |
                                             existing services + private verifier
                                             narrow host-administration adapter
```

Use application-owned authenticated static serving behind the **same existing Caddy instance**, rather than introducing a second reverse proxy, frontend server, Node runtime, Caddy file server, or public listener. The baseline Caddy already reverse-proxies to `/run/hfcache/api/api.sock`; retain TLS secret delivery, `admin off`, `auto_https off`, `persist_config off`, discarded default logging, and streaming behavior. Changes to templates must be minimal and justified. Caddy never receives an archive mount, Hub token, management password hash, or privileged host-administration socket.

Caddy forwards the client's Authorization header to the existing application. Do not impose a global Caddy `basic_auth` requirement in front of REST or MCP: it would obstruct their distinct bearer credentials. Do not translate Basic credentials into a shared hidden writer token or trust a client-supplied user header. Browser authentication is enforced by the application, including after proxying and on direct local socket requests. No public asset exception may expose archive data or private bootstrap metadata.

Let `P` be the validated configured public prefix, empty by default. Public routes are `P/ui/`, `P/api/v1/...`, and `P/mcp/`. Preserve current prefix-aware REST/MCP behavior and native Unix exemptions. Do not derive prefix, identity, or upstream selection from forwarded host/prefix headers. Same-origin fetches use deployment-generated paths, never a browser-configurable API address. An optional origin-root redirect is unnecessary; the documented entrypoint is `P/ui/`.

SPA fallback applies only to recognized UI navigation routes and GET/HEAD. Missing `/ui/assets/...` files, API typos, unsupported methods, and MCP errors must not return index HTML. Authenticate before route disclosure consistent with the existing API contract. An absent/disabled UI has an explicit authenticated unavailable/not-found result. A configured enabled UI with missing or mismatched release assets must fail its startup validation, not quietly serve another directory.

## 3. Build and release separation

Keep `web/` source and locked pnpm dependencies separate from Python runtime. Pin the selected compatible React/TypeScript/Vite/test tool versions during WEB-002; start from the repository's known Node/pnpm constraints rather than assuming a current version from memory. Document every new dependency, license, and runtime/build-time classification. Reused Cockpit code retains its LGPL notices; do not silently relicense it under the root project license.

Produce a separate, immutable **web asset artifact** alongside the wheel, with source commit, UI contract version, toolchain/lock digest, per-file hashes, and license notices. This deliberately avoids making base `uv build` or base reader installation invoke Node. The full release builder requires the UI artifact; a backend-only wheel still builds with the Python toolchain alone. Never commit `node_modules`, `dist`, browser profiles, or generated screenshots with credentials.

Native releases stage indexed assets under the immutable release directory. Rootless releases copy the verified asset artifact into a fixed read-only application-image directory, for example `/opt/hfcache/web-ui`. The API serves only that explicitly provisioned root; it is lexically and physically disjoint from archive, credentials, policy, and writable control state. Server web configuration is restart-only and defaults disabled for unchanged deployments. This is not a general `static_directory` exposed through browser configuration. Pin manifest/file identity and reject symlinks, special files, unsupported MIME types, traversal, oversized collections, and changes during capture. Avoid full-disk scans or per-request rehashing of large bundles; validate immutable asset indexes at startup and use bounded reads of indexed members.

Support empty and nonempty public prefixes without a new listener. Use relative Vite assets plus a safely rendered, deployment-derived UI base, or a deterministic equivalent tested on deep links. A small application-generated bootstrap resource under `/ui/` may carry nonsecret paths, UI/server contract versions, and the internal user's display/permission projection. It must be independently schema-versioned, `no-store`, and authenticated; it is not a new user-management API. Escape HTML/base metadata correctly and do not interpolate request headers into executable script. No inline executable scripts, `eval`, CDN fonts/scripts, external runtime requests, service workers, or offline archive-data caches.

HTML/bootstrap/API/card data: `Cache-Control: no-store`. Authenticated hashed static assets: conservative private caching; no shared cache, and no caching of user-specific output. Document update/chunk-mismatch handling that offers a reload without losing unsaved configuration or original operation handles. Do not silently refresh away uncertainty. Test a release switch with a page still open.

## 4. Authentication and authorization

Implement one independently provisioned human administrator via HTTP Basic over verified HTTPS. Use a protected username/password-hash record with a stable configured subject identifier. Prefer a maintained Argon2id implementation in the server optional dependency group; select/benchmark bounded verification parameters and record the dependency decision. No plaintext password persistence, hard-coded development password, or SHA-256-only password storage. Provision hashes through protected input, not command arguments or committed examples. Bound credential/header sizes, password-verification concurrency, and failed attempts; make wrong-user and wrong-password failures equivalent and avoid an unbounded per-client rate-limit map.

Authentication providers produce an internal principal with subject, authentication method, credential class, and capabilities. Bearer REST writer/reader and MCP-reader retain existing behavior. A Basic principal is REST/UI only and must never become an MCP-reader. Do not widen old `OperationView.principal` or `/capabilities` strict schemas merely to expose the username. Preserve old credential-class wire fields, while using separately versioned internal/audit identity when required; never claim historical receipts identify a human. Stable subject ownership is independent of password hash/rotation. Future OIDC/session providers should replace authentication without changing UI component authorization logic. Implement no signup, password reset, user database, OIDC flow, or repository ACL now.

UI components consume capabilities. Server-side policies enforce them; hidden controls are not authorization. Existing bearer writers must not acquire privileged host-administration authority by accident. New configuration/host actions require explicitly granted internal administrative capability **and** independently provisioned protected host policy. Basic admin login does not unmask services, make a read-only archive writable, permit Hub contact, or clear a deployment hold. Expose effective denied/unknown reasons through a safe permission projection. Do not amend the existing strict capability envelope in place.

Prefer the browser's native Basic challenge so JavaScript never receives the password. Prove the real challenge, retries, deep-link entry, and subsequent same-origin fetches in Chromium, Firefox, and WebKit; preinjecting Authorization into every request is not sufficient evidence. The UI must explain Basic's browser-managed credential lifetime and lack of a reliable application logout. Never display a fake secure logout. Production off-host Basic on plaintext HTTP is refused. Local Unix transport remains authenticated under the explicit server configuration.

### CSRF and request boundaries

Browser Basic is ambient authentication. For unsafe Basic-authenticated REST requests, require the exact configured same origin, JSON media type where applicable, and a non-simple application request header. Reject absent, `null`, duplicate, or unapproved Origin for those browser mutations. Reject simple form/text/multipart mutations and cross-origin preflights; do not enable permissive credentialed CORS. Fetch Metadata is defense in depth, not the only gate. Nonbrowser bearer clients retain their documented no-Origin behavior. Apply cheap request-size and authentication-work admission limits before password verification; authenticate and check permissions before parsing expensive candidate bodies or starting domain work. Bound queues/pools independently so failed login floods cannot consume every archive-operation observation slot.

Use a restrictive Content Security Policy: same-origin scripts/styles/connect, no plugins/frames/forms from cards, no unsafe-inline/eval; prevent framing and MIME sniffing. Referrer policy is no-referrer. Any `base-uri` allowance exists only for the controlled same-origin asset base, not README content. Test encoded Origin/Host/path cases, forwarded-header spoofing, redirects, and secrets in errors/traces. Do not redirect noninteractive REST/MCP clients into the SPA or a browser login flow.

## 5. Typed and bounded client boundary

Generate or mechanically derive precise transport types from server payload schemas, including the catalog's extension schemas and nested domain Envelopes. `ReadResponse.envelope` is currently generic: ordinary OpenAPI code generation alone does not provide strict domain typing. Define a schema registry/typed projection without changing stable wire wrappers unnecessarily. Validate `unknown` responses at runtime. Require `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, type-aware unsafe-assignment/no-explicit-any checks, and exhaustiveness for known state unions. Do not make every string an enum when the server allows extensible diagnostics.

Query/cache identities include authenticated authority, archive ID, repository type/ID, exact publication pair, and normalized filters. Do not cache full cards/configuration across accounts or changed archives. Abort stale reads on route/scope changes, not accepted backend work. Bounded pagination must preserve coverage and identity; 409 stale cursors restart the read walk with a visible explanation and finite retry budget. Never show zero as proof of absence when metadata coverage is incomplete, nor invent a global total from one page. Do not add duplicate aggregate endpoints to conceal a weak query layer.

Model sizes use exact integer-safe handling. JSON integer fields may exceed JavaScript's safe range: validate bounds and represent large values losslessly where supported, or fail explicitly before displaying/using a rounded selector or size. File manifests have finite API limits; render virtualized views without claiming they paginate at the server. Catalog detail has a bounded observation list; select exact publications to avoid unbounded retained-history reads.

## 6. Operations survive UI lifecycles

Record an original idempotency key in a bounded, nonsecret, authority-scoped registry **before** POST. Preserve the registry across routes, remounts, interrupted observation, and page reload within the supported browser session. Retain at most 32 records/64 KiB initially, aligned with the existing recovery contract; never evict unresolved entries. Store only validated action/route, key/ID, timestamps, and safe authority metadata, not request bodies, TOML, cards, credentials, or raw logs. Revalidate restored summaries against the original authenticated operation before unblocking submission.

No automatic POST retry, optimistic terminal success, cancellation, cleanup, or recovery after an uncertain response. Use original lookup/result/events. Missing/expired history remains unknown. 202 means admission, not completion. Event gaps, observation errors, and domain failure remain distinct. Interpret failed HTTP-200 Envelopes before reading success fields. Preserve warning/error codes and partial outcomes. Maintain the common mutation lane and benign busy behavior. Multi-tab coordination may improve presentation, but the backend remains authoritative; do not imply cross-tab cancellation or discard handles when tab-local storage disappears.

## 7. Configuration and host privilege separation

The current API container reads its policy directory; it must not be made root or given a host D-Bus socket, Docker/Podman socket, arbitrary shell, or broad writable `/etc` mount. Introduce a narrow host-administration helper boundary, documented by a new ADR, for fixed configuration installation and existing fixed schedule/observer actions. Use a protected Unix endpoint with verified actual peer identity, fixed operation grammar and allowlisted resources, finite messages, and effective host-policy proof. Container UID mapping must be proved; trusting a caller-provided username or UID is insufficient. Caddy and the verifier cannot contact this endpoint.

Keep the same persistent configuration lock inode used by the existing pipeline. The helper alone performs protected host writes, retains predecessor/candidate evidence, and validates exact base/candidate bytes. No HTTP request selects a filesystem path, shell command, service manager, unit name, service identity, secret source, or alternate archive. The helper has no Hub authority or archive payload access. It rechecks release binding and explicit permissions before effects. An absent/unsafe helper yields a classified unavailable/read-only UI, not a fallback.

Configuration applies and schedule/observer mutations require durable local outcome records and reconciliation after API/helper interruption. Reuse the operation infrastructure where safe; independently version new private state rather than weaken strict historical schemas. Define lock order and admission semantics before implementation. A long sizing preview cannot monopolize the configuration flock across Hub I/O. Preparation snapshots exact bytes under lock; validation/preview occurs outside it; installation reacquires and compares before atomic backup/replace/confirmation. New configuration changes future admissions, not already admitted jobs. Stale queued domain jobs must continue to refuse according to existing policy rules.

Host scheduling remains systemd. On the selected rootless profile, current system timer/observer bindings are unproved and effective permissions remain false. Show that state honestly; never silently redirect to identically named user-manager units or create a second scheduler. Positive schedule/observer paths are tested on an explicitly supported, bound disposable profile (including native). Verification timer is display-only; target shutdown/unmount is never a UI action.

## 8. Card content is untrusted derived metadata

Capture the root manifest-listed `README.md` during writer-owned sync/repair and existing technical metadata refresh. Missing README is a normal unavailable state; do not silently fetch it from the Hub or extend snapshot file selection. Read at most 1 MiB per card initially, with a separate maximum serialized presentation body of 1 MiB and shared aggregate writer/read budgets. Bounds are configurable only within a documented finite ceiling or fixed initially; tests must enforce actual bytes, Unicode expansion, node/work budgets, and whole-record writes.

Use a separately versioned `RepositoryCard` adjunct under an explicitly approved supplemental namespace, keyed by archive/repository/SHA/publication ID. It records exact manifest/source identity, capture status/time, presentation version, and a sanitized inert Markdown body when available. A bounded source digest comparison can ensure the copied README matches its manifest; this is a narrowly documented metadata-source check, not whole-publication verification or permission to raise integrity confidence. Amend the old 'refresh never hashes payloads' wording narrowly and explicitly if that check is used. The presentation digest describes sanitized output, never replaces the expected source digest.

Do not add a general file endpoint. Card GET reads only the adjunct, never the payload, Hub, or credentials; checks authoritative retention and exact publication identity; never falls forward when pruned/repaired. A stale adjunct cannot resurrect a purged repository. An old but still retained exact publication may remain readable only where current retention/reference rules authorize it. Independently preserve old manifests, refs, catalogs, and observations byte-for-byte. Extend existing `technical=true` refresh work to capture cards, preserving the old request/response shape and emitting bounded existing warning classifications; do not add a redundant card-refresh job route unless WEB-001 proves a concrete incompatibility and records the necessity.

Render Markdown using React components, GFM, and a reviewed sanitizer allowlist. Raw HTML/MDX is disabled; no `dangerouslySetInnerHTML`, remote code, plugins loaded from cards, SVG, scripts, iframes, forms, event handlers, unsafe protocols, or automatic external images/fonts. External assets display placeholders; no arbitrary URL/image proxy. Code is inert text. Rewrite safe relative links against pinned upstream identity, not arbitrary same-origin API/UI paths; external links use `noopener noreferrer`. Protect headings/IDs from DOM clobbering. A source toggle shows the **sanitized presentation source**, labelled as such, never unsuppressed original secrets. Parsing failure, unsupported structure, missing capture, oversize, invalid UTF-8 and suspicious content all have explicit non-success states without undoing valid archive publication.
