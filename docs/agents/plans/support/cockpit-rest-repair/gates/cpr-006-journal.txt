New cases exercise the actual collector and controlled process callbacks:
  - Exact fixed timeout/journalctl argv, no shell/archive path/user manager;
    invalid run IDs, traversal, leading options and URLs refuse before spawn.
  - Only the exact logger prefix event=<closed event> level=<known level>
    run_id=<requested lowercase32hex> renders. Wrong IDs, prefix extensions,
    unknown events, controls and a run ID embedded in quoted prose are filtered.
    Arbitrary trailing MESSAGE fields and synthetic credentials never render.
  - Empty successful EOF remains distinguishable from a process failure.
  - Chunk boundaries and oversized lines preserve only complete bounded events.
    A failed/deadline read does not promote an incomplete frame to an event.
  - The 201st line stops the owned diagnostic with explicit truncation;
    at most 200 whole lines and 64 KiB render, with an 8 KiB source-line bound.
  - A callback exceeding the remaining 256 KiB raw UTF-8 budget is discarded
    without retaining or encoding arbitrary oversized content. Only this owned
    read diagnostic is closed; the operation runner is not involved.
  - The deterministic client deadline requests exactly 6000 ms, closes the
    diagnostic and returns a classified timeout with bounded partial evidence.
  - Original bridge, access, host-timeout exit124 and launcher failures retain
    their safe classified facts independently of partial event lines.
  - Synchronous launcher/stream registration failure never retries. Hostile
    rejection getters are not invoked and raw rejection prose is not retained.

Pinned Cockpit buffering was inspected in
  cockpit/pkg/lib/cockpit.js: spawn().stream() assigns the channel buffer callback.
  cockpit/pkg/lib/cockpit/_internal/channel.js: a callback returning void consumes
  the complete current block and clears the buffer. This adapter therefore does
  not leave an independent accumulated stdout result behind its bounded decoder.

Boundary contract (ADR136):
  timeout --signal=TERM --kill-after=1s 5s journalctl
    --quiet --no-pager --output=cat --reverse --since=-7days --lines=201
    --case-sensitive=yes
    --grep=(^|[[:space:]])run_id=<validatedID>([[:space:]]|$)
    _SYSTEMD_UNIT=hfcache-sync.service
    _SYSTEMD_UNIT=hfcache-verify.service +
    _SYSTEMD_USER_UNIT=hfcache-api.service
    _SYSTEMD_USER_UNIT=hfcache-verification.service
  Arguments are individual fixed argv elements; the pattern is not a shell
  command. Explicit --reverse makes the newest-first order unambiguous even
  though --grep plus --lines also implies it. Rootless user-unit journal fields are
  matched without selecting a user manager or restricting to root's own UID.

RunJournal is an immutable diagnostic result with lines, truncated and fixed
truncationReasons. JournalReadError retains the original safe BoundaryError
classification plus immutable partial diagnostics. Administrative permission
and the captured host/connection generation are required; host profile effect
permission is not needed for this ordinary read. Journal absence, truncation,
failure or the seven-day horizon never determines a run outcome and never
prevents authenticated REST report access.

Official references checked for argv semantics:
  https://www.freedesktop.org/software/systemd/man/latest/journalctl.html
    Exact field matches of the same field are alternatives; + combines groups
    with OR. --grep with --lines returns newest entries first. --user-unit adds
    the caller UID, so fixed _SYSTEMD_USER_UNIT matches are used instead.
  https://www.freedesktop.org/software/systemd/man/latest/systemd.time.html
    Relative negative timestamps permit the fixed seven-day query horizon.
  https://www.gnu.org/software/coreutils/manual/html_node/timeout-invocation.html
    The 5s timeout sends TERM, with a further 1s before KILL if necessary;
    exit124 is the timeout marker. Other statuses retain their process meaning.
