Scope and boundary:
  New tests/installed_cli.py and tests/unit/test_cli_installed_socket.py implement
  the actual installed-wheel layer. The module is explicitly build-marked per
  test conventions and was explicitly executed; default deselection is not claimed
  as installed coverage. This layer changes no hfcache package source or durable
  format. A later helper-only runtime conformance repair is recorded separately
  in cpr-008-timer-facts.txt; it does not change these installed package bytes.
  Initial fixture construction assumed more than 100 package modules; actual
  inspection showed 90. Replaced that arbitrary assertion with exact equality of
  every source module path and every packaged Python path, plus byte equality of
  source, wheel and installed module. This was a harness correction, not a product
  regression and is not presented as behavioral RED evidence.

  The fixture builds a current wheel with uv build --offline --wheel, exports
  locked base dependencies with --locked --offline --no-dev --no-emit-project,
  creates an owned temporary venv with uv venv --offline, installs the locked
  closure with uv pip sync --offline, and installs the wheel with --offline
  --no-deps. It proves the console script's exact installed interpreter/import
  entry, resolves the imported package inside that environment, and checks every
  packaged Python byte against source and wheel. All invocations run outside the
  checkout, with deliberately hostile source PYTHONPATH ignored by Python -I,
  executing the actual installed console script through runpy.run_path.

  A child audit hook refuses the fixture archive, repository src, /srv/hfcache,
  /etc/hfcache and non-fixture socket connections. This establishes fixture-path
  isolation for these executions; it is not an OS sandbox against arbitrary path
  aliases or hostile native code. The real API/uvicorn listener uses a private
  temporary Unix socket, synthetic distinct credentials, the existing deterministic
  synthetic Hub backend and a synthetic verifier. No production credentials,
  production path, Hub HTTP, registry, host unit, NAS or live archive is used.
  Temporary archive creation uses existing application's fixture initialization,
  never an installed/live archive. This is not Cockpit/PAM/systemd/rootless proof.
