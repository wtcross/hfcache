CPR-008 manual-driver retained-profile preservation regression
2026-10-20; no guest, production, real browser or external network action.

Independent read-only review found that startFirefox(existingProfile) reused
private original-operation recovery state but its startup catch called close()
with default preserveProfile=false. A failed reopen could delete that retained
profile. The default close() after a successful reopen had the same unsafe
cleanup behavior. Root authorized both minimal preservation repairs and tests.

Baseline contributor saved the startup catch fix:
  await close(existingProfile !== undefined)
This contributor additionally changed the close parameter default to:
  preserveProfile = existingProfile !== undefined
Existing profiles are preserved automatically on failed startup and default close.
Fresh owned profiles keep the earlier explicit success/failure cleanup behavior.
The async classic-script evaluation wrapper and private existing-profile checks
are unchanged. No product application code, API, operation or cancellation changed.

Permanent tests: cockpit/test/runtime-bidi.test.ts, two cases.
They execute the actual runtime-bidi module and real cleanup/filesystem against
new owned private temporary profiles containing a synthetic original-handle
marker. Only child-process/protocol boundaries are controlled: a real owned Node
child exits17 during startup, or emits the bounded fixture endpoint and is closed
after a controlled successful session. No Firefox is launched and no socket is
connected. These are source/recovery-preservation regressions, not BiDi/Firefox/
PAM acceptance; actual about:blank and guest evidence belongs to separate records.
