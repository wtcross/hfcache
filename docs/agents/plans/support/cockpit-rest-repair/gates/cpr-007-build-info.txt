Boundary implementation reviewed:
  - Build-only Node helper reads declared regular public src/build/package/lock/
    Makefile/pkg-lib inputs. It excludes hidden/private fixture trees, rejects
    symlinks and nonregular public entries, and bounds scans to 1024 files,
    2 MiB per file, 16 MiB total, 4096 tree entries and depth 32. Sized reads plus
    an EOF probe avoid unbounded allocation if a public file grows during read.
    Linux traversal holds the selected root and every declared ancestor with
    O_DIRECTORY/O_NOFOLLOW/O_NONBLOCK and accesses only own /proc/self/fd
    directory anchors. Final leaf opens are read-only, nofollow and nonblocking.
    Unsafe ancestors or missing descriptor traversal refuse without a native
    path fallback; no external private leaf is opened to compute a rejected hash.
  - Production captures commit, working-copy state and framed public-input digest
    before the build and compares them after compression, before the existing
    remote-copy success hook. A failed build removes only generated repository
    dist output. Linux provenance capture requires the safe /proc/self/fd path.
    Development/watch and non-Linux production embed unknown provenance without
    changing the build's existing ability to produce a bundle on another machine.
  - Only the four strict public browser fields are embedded. Internal Git status,
    absolute paths, environment and private/fixture bytes are never emitted.
  - Diagnostics reuse existing typed host/client metadata and issue no extra
    automatic CLI invocation. An explicit client identity refresh uses only the
    existing fixed authenticated client describe command.
  - Selected and client metadata require current host, generation, administrative
    access, no pending refresh and no read error before presentation as current.
    Dirty/unavailable/mismatched browser state is explicit. Protected selected
    source/index/image and client profile/endpoint/class/archive/API instance are
    separate facts; neither those facts nor health readiness grant write/workload
    permission or prove the currently running API payload.
