# AD-18 — Prove archived bytes by local SHA-256 and exact object identity

- Status: accepted (amended 2026-08-10).
- ADR backfill: 2026-10-17; original decision and implementation dates are
  recorded below.
- Authority: the cited architecture contract remains normative. This ADR
  records rationale and history; maintain it under [the ADR policy](../../../../../adr/README.md).

## Context

Upstream identifiers, cache paths, and timestamps describe provenance,
not the bytes currently stored. Very large hardlinked snapshots also make
redundant full reads costly when an operation already hashed the exact
inode it is about to publish.

## Decision

Read and SHA-256 hash every newly introduced unique physical object
locally before publication. Reuse a retained publication's digest only
with proven same-inode and same-size evidence. Within one ingestion,
carry the freshly computed digest through hardlink staging only after
both source and destination match the exact `(device, inode, size)`
observed on the descriptor that supplied the hashed bytes. Keep that
identity transient. Hash a copied destination separately and compare it.

## Rationale and alternatives

Only reading bytes establishes their digest. Exact same-operation
identity lets a hardlink use that already obtained evidence without
another full read of the same physical object.

AD-18 rejects upstream Git SHA-1 or opaque Xet identifiers, cache paths,
mtimes, and prior-run inode numbers as substitutes for byte verification.
Decision 93 rejects removing the second read without identity proof and
persisting device/inode evidence for cross-run reuse.

## Consequences

The manifest records locally observed sizes and SHA-256 values.
Upstream-supplied digests are comparison metadata only. Same-operation
hardlink evidence retains `hashed = true`; it is not cross-run reuse.
An identity, completeness, or digest mismatch stops publication and never
rewrites the expected value to match corrupted content.
