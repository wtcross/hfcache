# AD-09 — Keep the canonical Hub download cache on the archive dataset

- Status: accepted.
- ADR backfill: 2026-10-17; original decision and implementation dates are
  recorded below.
- Authority: the cited architecture contract remains normative. This ADR
  records rationale and history; maintain it under [the ADR policy](../../../../../adr/README.md).

## Context

Large snapshots need resumable transfers and deduplication. Publication
also needs cache blobs and staged publication trees to share a filesystem
for hardlinks.

## Decision

Download through `snapshot_download()` into the writer-private
`<archive>/.store/hub` cache on the same ZFS dataset as publication. Expose
only the ordinary-file publication tree to consumers, never the Hub cache.

## Rationale and alternatives

The native cache provides resumability and revision deduplication. Its
placement makes AD-11's hardlink publication possible without another
content store.

The original record does not contain a separately enumerated rejected
alternative. Its rationale requires the native cache and same-dataset
placement; AD-10 separately rejects exposing cache internals to consumers.

## Consequences

The cache is operational state; published hardlinks preserve archived
bytes independently of cache revision eviction. Cache deletion uses the
supported public API. Interrupted downloads can reuse cached progress, and
repair uses a distinct transaction-scoped cache so it cannot trust or
modify the implicated canonical cache during verification.
