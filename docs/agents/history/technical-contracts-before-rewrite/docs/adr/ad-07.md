# AD-07 — Detect dependencies statically and never fetch them implicitly

- Status: accepted.
- ADR backfill: 2026-10-17; original decision and implementation dates are
  recorded below.
- Authority: the cited architecture contract remains normative. This ADR
  records rationale and history; maintain it under [the ADR policy](../../../../../adr/README.md).

## Context

A complete repository snapshot can still depend on a base model or
adapter elsewhere. Recursive dependency fetching would make one configured
repository an unbounded ingestion request, and discovering dependencies by
running repository code would expose writer authority to upstream code.

## Decision

Inspect known static metadata for dependencies, record observations in the
manifest, and report undeclared dependencies as non-fatal `HFDEP001`
warnings. Never execute repository content or download a transitive
dependency implicitly. Operators configure each desired repository
explicitly.

## Rationale and alternatives

Static detection makes missing runtime prerequisites visible while keeping
the archive's completeness, storage, and trust boundaries bounded to the
configured repository set.

The recorded decision rejects implicit recursive downloads and executable
dependency discovery. It does not claim that static metadata discovers all
possible runtime dependencies.

## Consequences

Dependency warnings can produce `completed_with_warnings` while preserving
exit status zero if nothing else fails. Unparseable or ambiguous metadata
is recorded without guessing. Repository completeness does not guarantee a
runnable environment (NG-04).
