# AD-10 — Publish immutable ordinary-file trees for consumers

- Metadata tool amendment: [decision 125](decision-125.md).
- Status: accepted.

## Context

The Hub cache uses symlinks into a private blob store. Consumers copying
that implementation layout over NFS would depend on cache internals and
could resolve links outside the intended exported tree.

## Decision

Publish regular files and directories at the repository's relative paths
under an immutable publication-instance directory. Consumers read one JSON
reference, copy the exact tree it names, and verify the copy against the
referenced manifest. Publication instances are never edited in place.

## Rationale and alternatives

An ordinary-file tree is independent of the Hub cache implementation and
requires no Hugging Face software on consumers. Immutable locators let
copies remain consistent while the current reference changes.

The original rationale rejects exposing or copying the symlink-based Hub
cache layout because it is fragile over NFS and couples consumers to a
private format.

## Consequences

A reference must never name a missing tree or manifest (FS-10). Consumers
mount only `published/` through a server-enforced read-only export. Repair
creates a new instance rather than overwriting one a consumer may already
be copying, and retains the old locator for its grace period.

## 2026-10-18 curated metadata tool amendment

[Decision 125](decision-125.md) registers exactly nine typed metadata tools via
an explicit narrow read capability, with no resources/prompts, OpenAPI conversion,
SDK app/request context, command/Hub/credential resolver or writable helper.
Read-only annotations describe the capability; registry/schema equality and
success/failure archive/control-state snapshots must prove it.

Shared validated readers preserve exact SHA/publication identity, canonical
locator bases and unknown derived confidence without writes or reconstruction.
Manifest/report pages are explicit projections, not complete durable artifacts;
headers preserve original totals/report provenance and complete source content
binds cursors. Missing/stale instances refuse rather than substituting current.
Archive-derived strings and dependency observations remain untrusted data, never
instructions or executable content. Consumer copy/verification/promotion and
whole-archive authorization remain unchanged. No dependency, config/durable
schema, job path or production operation is added. See [MCP](../mcp.md) and the
[recorded deployment scope](../deployment-status.md).
