# AD-20 — Remove whole repositories only through explicit unmanaged purge

- Status: accepted.

## Context

A long-lived archive needs an intentional way to release unwanted
repository content. Upstream failures and configuration edits must retain
their non-destructive semantics, and removing a repository file by file
must not expose partial retained state or bypass audit and recovery.

## Decision

Provide a separate `purge` command for repositories already absent from
configuration. Require exactly one of `--dry-run` or `--apply`, explicit
selectors or explicit `--all-unmanaged`, and revalidation under the writer
lock. Use one transaction per repository and reuse the prune logical
commit point and recovery rule.

## Rationale and alternatives

An explicit command makes destructive scope reviewable. Whole-repository
validation and tombstoning preserve honest per-repository failure
boundaries while reusing an established crash-safety protocol.

Decision 96 rejects deletion on configuration edit, manual filesystem
removal, repeated one-revision prunes, and a new journal operation literal.
Those choices respectively risk accidental loss, bypass safety/audit,
expose partially retained repositories, or duplicate recovery semantics.

## Consequences

Unexpected shallow layout entries refuse the entire repository. Remove
cache revisions only through supported Hub APIs, tombstone references and
trees before manifests, and retain original manifests and reason records
in `audit/pruned/`. Before the logical commit, recovery restores content;
after it, recovery completes audit/cleanup without republishing. A broad
purge is not atomic across repositories. An open purge journal blocks
rollback to an older reader; completed state has the separately drilled
compatibility described by decision 97.
