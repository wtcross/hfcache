# AD-08 — Reach the Hub through the official injectable Python adapter

- Status: accepted.

## Context

Ingestion, cache inspection, and cache cleanup need typed failures and
stable boundaries. Shelling out to multiple Hub and Git tools would tie
correctness to subprocess behavior and scraped output.

## Decision

Use the public `huggingface_hub` Python APIs behind a narrow injectable
adapter for all Hub interaction. Do not invoke `hf`, `git`, `git-lfs`, or
`git-xet` as application subprocesses. Pass application-owned types outside
the adapter and use supported cache APIs rather than parsing cache names.

## Rationale and alternatives

The adapter contains upstream API changes and exception translation in one
place. Injectable deterministic fakes exercise ingestion without network
access or monkeypatching library internals.

The original decision rejects subprocess orchestration because it obscures
typed results, hides failures, and couples the archive to CLI text formats.
Framework boundary FW-03 also keeps runtime dependencies deliberately
small; additions require FW-04's correctness argument.

## Consequences

The adapter translates library errors into stable hfcache taxonomy codes.
Every request receives an explicit credential value or `token=False`,
avoiding ambient credential discovery. Default tests remain offline;
real-Hub checks use an opt-in live suite.
