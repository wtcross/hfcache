# AD-12 — Keep durable authority in versioned filesystem JSON

- Status: accepted.
- ADR backfill: 2026-10-17; original decision and implementation dates are
  recorded below.
- Authority: the cited architecture contract remains normative. This ADR
  records rationale and history; maintain it under [the ADR policy](README.md).

## Context

The archive is a single-writer NFS filesystem whose published bytes and
manifests must remain understandable after crashes and software rollback.
A separate mutable database would introduce another state authority.

## Decision

Represent manifests, references, catalogs, reports, and journals as
versioned JSON files written atomically. Do not use SQLite or another
mutable database on NFS. Rebuild derived catalogs from immutable manifests
and references; do not let a catalog override archive evidence.

## Rationale and alternatives

A filesystem-authoritative archive can be inspected and recovered from its
own durable artifacts. A database on NFS adds locking behavior and the
possibility of disagreement between database state and the published tree.

The original decision explicitly excludes SQLite and other mutable NFS
databases. The related framework boundary excludes an orchestration engine
with its own persistent state for the same reason.

## Consequences

Each durable artifact carries `schema_version`; unknown versions are
refused. JSON serialization and array ordering are deterministic. Durable
updates use temporary siblings, fsync, and same-filesystem replacement.
Schema compatibility, forward fields, and cross-release rollback drills
follow their governing contract rather than being inferred from JSON's
flexibility.
