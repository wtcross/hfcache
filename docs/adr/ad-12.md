# AD-12 — Keep durable authority in versioned filesystem JSON

- Status: Amended; see decisions 133 and [157](decision-157.md).
- Replacement design: see the 2026-10-20 amendment below; executable conformance remains pending.

## Context

The archive is a single-writer NFS filesystem whose published bytes and
manifests must remain understandable after crashes and software rollback.
A separate mutable database would introduce another state authority.

## Decision

Represent manifests, references, catalogs, reports, and journals as
versioned JSON files written atomically. Do not use SQLite or another
mutable database on NFS. Rebuild derived catalogs from immutable manifests
and references; do not let a catalog override archive evidence.

## Rationale and alternatives

A filesystem-authoritative archive can be inspected and recovered from its
own durable artifacts. A database on NFS adds locking behavior and the
possibility of disagreement between database state and the published tree.

The original decision explicitly excludes SQLite and other mutable NFS
databases. The related framework boundary excludes an orchestration engine
with its own persistent state for the same reason.

## Consequences

Each durable artifact carries `schema_version`; unknown versions are
refused. JSON serialization and array ordering are deterministic. Durable
updates use temporary siblings, fsync, and same-filesystem replacement.
Schema compatibility, forward fields, and cross-release rollback drills
follow their governing contract rather than being inferred from JSON's
flexibility.

## 2026-10-17 control-state amendment

[Decision 114](decision-114.md) adds an independently versioned service-private
local JSON family for operation receipts/events/result references. Its durable
receipt binds admission and hashed idempotency identity; indexes are derived.
It neither changes an archive format nor competes with manifests/journals as
archive authority. Unknown or ambiguous local records are preserved and refuse
admission, with no journal-driven replay. The no-database rule and deterministic
atomic filesystem conventions remain intact.

## Supplemental discovery amendment (2026-10-19)

[Decision 133](decision-133.md) defines proposed tag/curation identities, the narrow
independent-atomic adjunct exception and protected read capabilities. Existing
archive, candidate-byte, whole-archive authorization and registered MCP boundaries
remain in force until corresponding additive implementation is accepted. Tags do
not change operational policy identity or grant installation/write authority.

## Replacement UI design amendment (2026-10-20)

[Decision 142](decision-142.md) amends this record for the accepted
replacement design. Accepted independent card and private administration/asset families remain versioned and do not widen old strict durable schemas; their implementation and compatibility evidence is pending.

## Source implementation clarification (2026-10-21)

The earlier replacement-design amendment records the introduction-stage state.
The independent static manifest/bootstrap family is now implemented in unreleased
source under [decision147](decision-147.md); it changes no archive manifest,
reference, run receipt or `/capabilities` schema. Card adjunct and privileged
administration families retain their separate implementation and compatibility
requirements. Source implementation alone establishes no installed compatibility,
clean release or complete replacement acceptance. See the
[versioned record boundaries](../schemas.md#18-web-ui-and-administration-design-records).

## Independent card capture clarification (2026-10-25)

[Decision 142](decision-142.md#writer-capture-amendment-2026-10-25) now has a
writer implementation in unreleased source. Its strict schema-1 card family is
independent of observations, manifests, references and public refresh wrappers;
their versions and byte meanings remain unchanged. The 2 MiB whole-card bound
is separate from other supplemental record bounds. Actual previous-binary
compatibility must be measured before rollback is claimed; a new optional path
can legitimately be refused by an older writer. Card API/rendering remain later
work, not implied by durable capture.

## Fresh-byte parsing refinement (2026-10-27)

[Decision157](decision-157.md) permits bounded reuse of frozen parsed references
and manifests only after a fresh anchored read produces identical bytes. Every
read still charges its query budget; current membership and publication context
remain independently checked. The process-local parser memo supplies no durable
authority and no prior query result. Filesystem JSON remains authoritative.
The refinement is implemented in unreleased source; implementation does
not supply final matching browser-performance or installed-profile acceptance.
