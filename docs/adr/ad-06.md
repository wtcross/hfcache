# AD-06 — Preserve local content when upstream or configuration changes

- Status: accepted.
- ADR backfill: 2026-10-17; original decision and implementation dates are
  recorded below.
- Authority: the cited architecture contract remains normative. This ADR
  records rationale and history; maintain it under [the ADR policy](README.md).

## Context

The archive is most valuable when upstream is unavailable. An access
failure, deleted repository, or accidental configuration edit must not
become authority to destroy preserved revisions.

## Decision

Upstream `403` or `404`, repository deletion, gating, network failure,
credential revocation, and removal from configuration preserve local
revisions. Record and report the changed state. Normal retention follows
successful publication; whole-repository removal requires the explicit
unmanaged-only purge workflow introduced by AD-20.

## Rationale and alternatives

Availability and configuration state describe whether future ingestion is
possible or desired. They do not prove that existing archive content is
safe to delete.

Automatic deletion on upstream disappearance or configuration removal is
excluded by the original decision. AD-20 later explicitly rejects making
configuration edits destructive.

## Consequences

Unconfigured repositories remain discoverable as unmanaged and remain in
full verification. A failed upstream lookup cannot trigger retention.
Removing retained restricted content requires configuration removal and
explicit purge, even after credentials lose access.
