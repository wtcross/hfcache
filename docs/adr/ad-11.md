# AD-11 — Use hardlink publication by default and require explicit copy mode

- Status: accepted.
- ADR backfill: 2026-10-17; original decision and implementation dates are
  recorded below.
- Authority: the cited architecture contract remains normative. This ADR
  records rationale and history; maintain it under [the ADR policy](README.md).

## Context

Large ordinary-file publication trees must fit the archive's capacity
model. Hardlinks can expose cache bytes without doubling storage, while a
copy fallback could unexpectedly consume an entire additional snapshot.

## Decision

Default to `publication_mode = "hardlink"` and hardlink approved cache
blobs into staging on the same dataset. Copy mode is an explicit operator
choice following capacity review. If the required hardlink capability is
unavailable, fail preflight before downloading instead of falling back.

## Rationale and alternatives

Hardlinks provide the consumer-facing ordinary-file layout at no extra
content storage. Failing early keeps the configured capacity policy true
through large transfers.

The original decision explicitly rejects silent fallback to copy because
it multiplies storage without warning and may fill the dataset during a
run. Copy remains a supported deliberate alternative.

## Consequences

Capability probes establish hardlink, same-filesystem atomic rename, and
atomic-reference behavior on the real dataset. Never chmod a hardlinked
file because it shares the cache inode. Directory modes and export policy
provide consumer access. Copy mode accounts for extra allocation and hashes
the distinct landed object; hardlink mode proves same-object identity.
