# AD-15 — Treat repository content as untrusted data

- Metadata tool amendment: [decision 125](decision-125.md).
- Bounded writer-owned static observations: [decision 133](decision-133.md).
- Status: Amended; accepted untrusted-content boundary with the card design addition below.
- Replacement design: see the 2026-10-20 amendment below; executable conformance remains pending.

## Context

The writer ingests arbitrary third-party files while holding archive
mutation authority. Executing or deserializing executable repository
content would give an upstream author access to that authority.

## Decision

Never execute, import, unpickle, or instantiate repository content, and
never enable `trust_remote_code`. Accept only validated repository paths
and approved regular-file sources contained by the operation's cache root.
Use known static metadata formats for dependency detection.
Supplemental discovery may read selected exact-manifest published ordinary files
through no-follow access with shared byte/work/structure bounds. It retains only
allowlisted inert declarations, never follows their URLs, and leaves unsupported
facts unknown. Existing dependency detection semantics are unchanged.

## Rationale and alternatives

Storage authority must remain separate from the content being stored.
Static parsing and containment checks allow preservation without trusting
repository code or allowing a path to escape into host or archive state.

The decision explicitly excludes executable dependency discovery, model
loading, unsafe deserialization, and trusting repository-supplied paths.
These are architectural exclusions rather than configurable convenience
features.

## Consequences

Reject absolute and escaping paths, spelling/collision hazards, dangling
links, and non-regular objects before link or copy. A Hub-cache symlink is
accepted only after its target is proven to be an approved regular cache
object. Archive completeness does not include running model or dataset
code, resolving external dataset payloads, or ensuring a runtime.

## 2026-10-18 curated metadata tool amendment

[Decision 125](decision-125.md) registers exactly nine typed metadata tools via
an explicit narrow read capability, with no resources/prompts, OpenAPI conversion,
SDK app/request context, command/Hub/credential resolver or writable helper.
Read-only annotations describe the capability; registry/schema equality and
success/failure archive/control-state snapshots must prove it.

Shared validated readers preserve exact SHA/publication identity, canonical
locator bases and unknown derived confidence without writes or reconstruction.
Manifest/report pages are explicit projections, not complete durable artifacts;
headers preserve original totals/report provenance and complete source content
binds cursors. Missing/stale instances refuse rather than substituting current.
Archive-derived strings and dependency observations remain untrusted data, never
instructions or executable content. Consumer copy/verification/promotion and
whole-archive authorization remain unchanged. No dependency, config/durable
schema, job path or production operation is added. See [MCP](../mcp.md) and the
[recorded deployment scope](../deployment-status.md).

## Accepted catalog read extension (2026-10-19)

[Decision 133](decision-133.md) and the accepted discovery amendment to
[decision 125](decision-125.md) extend the registry from nine to fourteen explicit
read-only tools. The five additional catalog reads share bounded local queries
through a separate narrow async port. They add no mutation, Hub, credential,
arbitrary file/URL dispatcher, resource, prompt or job authority. Whole-archive
authorization, inert repository content and exact immutable publication identity
remain required.


## Replacement UI design amendment (2026-10-20)

[Decision 142](decision-142.md) amends this record for the accepted
replacement design. Accepted card presentation design retains bounded inert data, exact manifest provenance, no execution/HTML/remote assets and no payload capability for read requests; conformance is pending.

## Inert capture clarification (2026-10-25)

[Decision 142](decision-142.md#writer-capture-amendment-2026-10-25) now separates
implemented writer capture from later API reads and rendering. Capture never
executes content or fetches links/assets. Full-source secret detection precedes
omissions and suppresses the whole presentation on a match; unsupported or
unsafe content retains only fixed diagnostics and exact source identity. The
fresh README digest checks a bounded metadata copy, not whole-publication
verification. Retained Markdown remains untrusted inert data; the future renderer
must still enforce the independent HTML, protocol, media and navigation controls.
