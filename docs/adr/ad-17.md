# AD-17 — Use one writer host and one local exclusive lock

- Status: accepted.
- ADR backfill: 2026-10-17; original decision and implementation dates are
  recorded below.
- Authority: the cited architecture contract remains normative. This ADR
  records rationale and history; maintain it under [the ADR policy](README.md).

## Context

The deployment grants archive write access to one dedicated host.
Concurrent local commands still need mutual exclusion, but a distributed
lock would add failure modes without providing an additional authority
boundary.

## Decision

Enforce one writable host through the exact-host server export policy.
Serialize archive-affecting commands through the same local exclusive lock
under `/run/hfcache`, outside NFS. Do not add leader election or
distributed coordination. A second writer is an architectural change.

## Rationale and alternatives

A local lock is sufficient when the server permits only one host to
write. Avoiding NFS locks removes unnecessary distributed locking behavior
from the archive's correctness assumptions.

The original record rejects distributed locking and lock files on NFS,
which buy nothing under the single-writer deployment. Per-command locks
would not exclude different mutating commands from one another.

## Consequences

Sync, verification, prune, purge, repair, recovery, and explicit quarantine
cleanup honor the shared archive lock where their contracts require it.
The download-ahead worker remains inside the owning sync process and must
finish before that lock is released. The export's host restriction and
local lock solve different parts of the single-writer guarantee.
