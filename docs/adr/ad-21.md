# AD-21 — Require explicit restricted Hub scope and one consumer authorization boundary

- Metadata tool amendment: [decision 125](decision-125.md).
- Status: accepted; candidate/reader authority clarified by
  [decision 119](decision-119.md), with distinct MCP-reader transport in
  [decision 124](decision-124.md).

## Context

The original scope was public repositories only, although credential
configuration anticipated a later extension. The deployed private network
needs to archive repositories that its service account is authorized to
read, while the exported publication tree has no per-repository ACL layer.

## Decision

Make `hub.token_mode = "required"` the sole opt-in for private and gated
repositories. Resolve an explicit token file or systemd credential before
Hub contact and pass that credential to every Hub call. Keep `disabled`
and `optional` public-only, even if optional mode finds a token. Require
every consumer of the published tree to be authorized for every archived
repository.

## Rationale and alternatives

Explicit scope separates authorization policy from ambient credential
availability. One shared consumer boundary matches the actual export
rather than promising repository isolation that the publication tree does
not enforce.

AD-21 and decision 98 reject automatic restricted scope from an optional
token, per-repository credentials/ACLs for this shared-boundary deployment,
and deletion when a credential or gate loses access.

## Consequences

A missing required credential is `HFARG008` at exit 10. Public-only modes
refuse restricted repositories with `HFHUB006`; an unaccepted gate under
required mode is an access failure (`HFHUB005`). Revocation stops future
fetches without deleting published content. Explicit configuration removal
and purge provide the deletion path. No durable JSON shape changes; the
configuration fingerprint already captures access intent. Rollback to a
pre-Hub access binary requires stopping sync and returning configuration to
optional mode without syncing restricted repositories on that release.

## 2026-10-18 reader/candidate amendment

REST readers share the same whole-archive authorization boundary as reports and
published metadata; no repository ACL is introduced. Writer candidate validation
resolves no Hub credential, and syntax validity is separate from installed
authority compatibility. Candidate planning must preserve all six installed
authority fields, checked again after queue waiting before installed credential
use. A proposed token mode, endpoint or credential source cannot expand installed
privilege. See [decision 119](decision-119.md),
[candidate policy](../configuration.md#12-candidate-authority-validation-and-planning)
and [adversarial coverage](../../tests/unit/test_api_candidates_adversarial.py).

## 2026-10-18 MCP-reader transport amendment

[Decision 124](decision-124.md) implements a separate fixed MCP-reader credential
through shared protected opaque-token validation. This capability covers the
whole archive, including restricted metadata; it introduces no repository ACL,
individual identity or credential forwarding. REST and MCP credentials cannot
cross interfaces, and session identifiers grant no access. No tools/resources/
prompts are registered in this design; curated tools remain curated metadata tools and must
retain the same consumer authorization boundary without commands, Hub or probes.

## 2026-10-18 curated metadata tool amendment

[Decision 125](decision-125.md) registers exactly nine typed metadata tools via
an explicit narrow read capability, with no resources/prompts, OpenAPI conversion,
SDK app/request context, command/Hub/credential resolver or writable helper.
Read-only annotations describe the capability; registry/schema equality and
success/failure archive/control-state snapshots must prove it.

Shared validated readers preserve exact SHA/publication identity, canonical
locator bases and unknown derived confidence without writes or reconstruction.
Manifest/report pages are explicit projections, not complete durable artifacts;
headers preserve original totals/report provenance and complete source content
binds cursors. Missing/stale instances refuse rather than substituting current.
Archive-derived strings and dependency observations remain untrusted data, never
instructions or executable content. Consumer copy/verification/promotion and
whole-archive authorization remain unchanged. No dependency, config/durable
schema, job path or production operation is added. See [MCP](../mcp.md) and the
[recorded deployment scope](../deployment-status.md).

## Accepted catalog read extension (2026-10-19)

[Decision 133](decision-133.md) and the accepted discovery amendment to
[decision 125](decision-125.md) extend the registry from nine to fourteen explicit
read-only tools. The five additional catalog reads share bounded local queries
through a separate narrow async port. They add no mutation, Hub, credential,
arbitrary file/URL dispatcher, resource, prompt or job authority. Whole-archive
authorization, inert repository content and exact immutable publication identity
remain required.
